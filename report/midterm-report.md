## 1. 今回取り組む課題の内容（課題1）

> 詳細・経緯: [who-eats-narrative.md](./who-eats-narrative.md)

### 1.1 背景となる問題意識

本班が取り上げる **主たる社会課題** は、大学生が **急な一人暮らし** を始めた際に、**食生活の管理がうまくいかず偏食や食の偏りが続く** ことである。

- 食事の時間・内容を自分で管理する負担
- 自炊が続かない、または同じ食事の繰り返し
- 外食・コンビニへの偏り、朝食抜きなど **食事回数・栄養の乱れ**

班内では、上記を **自分たちや周囲の実体験** として共有した。

**関連する副次的課題** として、外食時に匿名レビューだけでは信頼できる選択が難しい点もある。これは課題2以降、友達の投稿と地図機能で **手段として** 扱う。

### 1.2 社会的な意義・普遍性

本課題は **外食時の意思決定支援** に関するものであり、大学生に限らず、旅行・転居・コミュニティ活動など **「他者の体験を参考にする」** 場面に普遍性がある。特に SNS を日常的に利用する層では、すでに人とのつながりから情報を得ているが、それを **構造化・地図上で再利用可能** にすることで、以下の社会的価値が期待できる。

- 失敗体験（期待と実態のギャップ）の削減
- 信頼関係に基づく情報共有による、匿名口コミへの過度な依存の緩和
- 大学キャンパス周辺など、生活圏が近い人の行動ログという実用的な推薦

### 1.3 課題設定の経緯

| 段階 | 内容 |
|------|------|
| 当初 | 自炊・食事管理に特化したアプリ案 |
| 問題 | 入力負荷が高く **持続しない** |
| 転換 | **日々投稿しやすい SNS** と **友達との共有** |
| 現在 | 自炊・外食を同一フローで記録する **Who eats** |

### 1.4 既存の解決方法の調査結果

| 手段 | 概要 | 本課題に対する限界 |
|------|------|---------------------|
| カロリー・献立アプリ | 数値・献立管理 | 継続しにくい |
| Google マップ / 食べログ | 店・匿名レビュー | **食生活全体・偏食** は見えない |
| 一般 SNS | 食事写真の共有 | 偏りの分析・振り返りに弱い |

**結論**: 「管理だけ」「グルメだけ」では不十分。**偏食を防ぎ、続く記録** が必要。

**図1（案）**: 現状と理想の情報フロー — `report/assignment-1-social-issue.md` 内の mermaid 図を PDF 用に画像化して掲載。

## 2. 課題解決方法（課題2）

### 2.1 問題の具体化・何をどこまで解決するか

**プロダクト名**: Who eats  
**本質**: 一人暮らし大学生等の **食生活の偏り・偏食を防ぐ** ための、**続く** 食事記録と友達共有  
**手段**: 食事投稿 SNS、友達フィード、地図（外食時の選択支援）

| 解決する範囲（課題3） | 範囲外（展望） |
|------------------------|----------------|
| 認証、**自炊／外食**の投稿、タイムライン、地図、フォロー、いいね・コメント、記録タブ | **AI 画像解析による偏り分析** |
| デモ: ログイン→投稿→友達のフィード→振り返り | **1日1・2・3食の厳密管理** |
| | **栄養士スポンサー・事業化**（計画段階） |

授業の時間制約を踏まえ、**プロトタイプでコア体験を示し、展望はレポートで明示** する。

### 2.2 解決方法のアプローチ・利用技術の概要と調査

#### 2.2.1 アーキテクチャ

クライアントに **Flutter（OSS）**、バックエンドに **Supabase（OSS コア + 無償枠）** を採用する。地図・店舗情報には **Google Maps / Places API**（無償枠内）を利用する。

```
[Flutter App] ──► [Supabase: Auth / PostgreSQL / Storage / RLS]
       │
       └──► [Google Maps / Places API]
```

**選定理由**

- Flutter: 1 コードベースでモバイル UI を構築でき、授業デモに適する。
- Supabase: RLS 付き PostgreSQL で短期間に認証・DB・画像保存を実現できる。
- いずれもオープンソースまたは無償枠で改変・学習が可能（課題2の要件を満たす）。

#### 2.2.2 主要機能

| 機能 | 説明 |
|------|------|
| 投稿 | 写真必須、店紐付け（位置情報候補＋手動修正）、自炊可 |
| タイムライン | 友達／近い人／全体のスコープ切替 |
| 地図 | 店ピン、店詳細、フィードからの地図フォーカス |
| ソーシャル | フォロー、いいね、コメント、`@user_code` 検索 |
| プロフィール | 初期フィード表示の設定、記録タブ |

**図2（案）**: 画面遷移図 — `doc/whoeats-screen-spec-v1.md` から主要画面を抜粋して掲載。

### 2.3 実現に向けたシナリオ

**代表シナリオ**

1. ユーザー A が外食後、写真と店情報を投稿する。
2. 友達 B がホーム（友達スコープ）で A の投稿を閲覧し、いいね・コメントする。
3. B がマップで A が行った店のピンを確認し、店舗詳細から地図上の該当位置へ遷移する。
4. B が `@user_code` で C を検索し、フォローして相互フォロー（友達）になる。
