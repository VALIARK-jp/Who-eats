## 1. プロジェクトの位置づけ（授業・6人班）

- **プロダクト**: 「友達の食体験で店を選ぶ」グルメマップ系モバイルアプリ（Flutter）。
- **現状**: **UIプロトタイプ＋地図周りの実装が進んだ段階**。バックエンドの自社DB・認証・本番投稿フローは**未接続**（モック／外部APIの組み合わせ）。
- **PMの役割の例**: アーキテクチャ方針・難所（テーブル設計、API契約、キー管理）のオーナー、レビュー、スプリント境界の調整。  
- **メンバー向け**: 「コンポーネントを一から作る」機会が少ないフェーズでも、**仕上げ・追従・検証・ドキュメント**に十分ボリュームがある（後述）。

## 3. アーキテクチャ概要（ファイルの見方）

```
lib/
  main.dart
  src/
    app.dart                          # DI: Repository / Controller 生成、MaterialApp
    core/
      config/app_config.dart          # dart-define（API URL、Googleキー、投稿ピン用など）
      theme/app_theme.dart
    features/dashboard/
      domain/                         # エンティティ・Repository抽象・UseCase
      data/                           # Mock / Remote（Map API、Google Places）
      presentation/
        controllers/app_shell_controller.dart
        pages/app_shell_page.dart     # 画面の大半（タブ・ホーム・マップ・シート等）
        widgets/food_pin_3d_viewer.dart
```

- **データ取得**: `DashboardRepositoryImpl` が **Google Places（任意）→ 自前 Map API（任意）→ Mock** の順でフォールバック。
- **設定**: `AppConfig`（`WHOEATS_MAP_PINS_API_URL` 等）。`.env` 運用（`flutter run` で読込、詳細は [README.md](../README.md)）。

## 4. 実装済み（Done）— いま動いている範囲

### 4.1 アプリシェル・ナビゲーション

- 下部 **5タブ**（ホーム / 友達 / 撮影 / 記録 / プロフィール）。
- ホーム内 **横スワイプ**で「フィード」と「マップ」を切替（`PageView`）。

### 4.2 ホーム・フィード

- フィード一覧（モック `FeedPost`）、いいね数・コメント数・友達アバター表示などの**プロトタイプUI**。

### 4.3 マップ（コア実装が厚い領域）

- **Google Map** 表示、現在地、デフォルトPOI非表示スタイル。
- **ズームに応じた表示切替**: 広域はクラスタ風の集約マーカー、中〜詳細は個別ピン。
- **ビューポート連動**: カメラ位置に応じたピン取得・検索のフック（コントローラ経由）。
- **マップ上検索**（展開UI、デバウンス）。
- **3Dピンオーバーレイ**: 画面上のスクリーン座標に WebView を重ね、通常ピン用 HTML と **「投稿ピン」用** `3d_pin_posted.html` を切替。
- **投稿ピン**: `dart-define` の `WHOEATS_POSTED_PIN_PLACE_ID` / `WHOEATS_POSTED_PIN_PLACE_NAME`、または `isFriendVisited` などで対象店を解決。アイコンはアセットから **chunk 分割で base64 注入**（長い JS 文字列による iOS 失敗の緩和）。
- **パフォーマンス**: マップ **パン／ズーム中** は 3D アニメの目標 FPS を下げ、**カメラ停止後** に 30fps へ戻す（`ValueNotifier` + `window.setTargetFps`）。

### 4.4 店舗・投稿まわり（UI＋データ層の一部）

- マップピンタップ → **ボトムシート**（店名・評価・友達コメント・投稿プレビュー等）。
- **店詳細**取得ユースケース（モック／リモート JSON 形式は README 記載）。
- **撮影タブ**からモック `PostDraft` を生成し、**投稿エディタ**（ボトムシート）を表示。Places オートコンプリート等のフックあり（実装は `app_shell_page` 内に集約されがち）。

### 4.5 その他タブ（プロトタイプ）

- **友達候補**一覧、**記録サマリー**、**プロフィール概要**、**通知** — いずれも主にモックデータ駆動の UI。

### 4.6 非機能・開発者向け

- API 未設定時も **モックで画面が破綻しない** 方針。
- [TODO.md](../TODO.md): iOS/Android の **Maps API キー手順**、本番 URL 差し替えチェックリスト。

## 8. メンバー5人への振り方（PM用メモ）

1. **「新規コンポーネントが少ない」→ 仕様差分の列挙と小さな抽出 PR に分解**する（上表 T1〜T10）。
2. **大きいファイル（`app_shell_page.dart`）は触る人を週1人に限定**し、それ以外は `theme` / `widgets` / `doc` で並列化。
3. **レビュー観点を短く固定**する例: 「挙動変化なし」「スクショ1枚」「dart analyze」。
4. **バックエンド・ER・キー**は PM がホールドし、メンバーには **入出力 JSON と画面**だけ見せてタスク化すると迷子が減る。
