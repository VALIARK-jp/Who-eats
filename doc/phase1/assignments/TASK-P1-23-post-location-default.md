# TASK-P1-23: 投稿時の位置情報（GPS）の取り方と権限まわりを仕上げる

> **親ドキュメント**: [TASKS.md](../TASKS.md) の「投稿（PM最小のあと）」  
> **ブランチ名の例**: `feature/p1-23-post-location`

---

## 目的

- 外食投稿で **近くの店候補**を出すために、位置情報を **タイミングよく・失礼のない説明で**取得する。
- **拒否された場合**でも、手動で店を選べる流れに迷わず入れる。

---

## 説明

### アプリ上でどう見えるか

- 初回はOSの **「位置情報を許可しますか？」** ダイアログが出る（Apple/Googleの仕様）。
- 拒否した人には **「設定から許可できます」** など次の一手が分かる画面またはリンク。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **権限（パーミッション）** | カメラ・位置情報など、**ユーザーが許可するまで使えない**もの。 |
| **`Geolocator` 等のパッケージ** | 位置を取るためのよく使われるライブラリ（採用はチーム合意）。 |

### 前提（先に終わっていること）

- PM最小の投稿フローがある。
- **店候補API** が緯度経度を受け取れる（または受け取らない方針がPMから文書化されている）。

---

## 方法

### 非エンジニアの方へ（進め方）

1. **なぜ位置が必要か**をユーザー向けに **2文以内**で書く（設定画面やダイアログに使う）。
2. **拒否したあと**にどの画面へ誘導するか（設定アプリを開くボタンを出すか等）をPMと決める。
3. テスト: 許可／拒否／後から許可、の3通りを **手順書**にする。

### エンジニアの方へ（実装の進め方）

1. **`permission_handler`** 等で **`Permission.locationWhenInUse.request()`** の流れを実装（パッケージ名は `pubspec.yaml` に合わせる）。
2. 位置取得は **`Geolocator.getCurrentPosition`** または **`getLastKnownPosition`**（精度とバッテリーのトレードオフはPM相談）。
3. 取得中は **`CircularProgressIndicator`** か **`LinearProgressIndicator`** を **`Stack`** で重ねる。
4. 座標は **`LatLng(lat, lng)`** のような型にまとめ、店検索APIに渡す **1か所**に集約する。

### 使うとよいウィジェット・プロパティの例

| やりたいこと | ウィジェット / API 例 | ポイント |
|--------------|------------------------|----------|
| 説明文 | `Text` + `TextButton` | **設定を開く** は **`openAppSettings()`**（パッケージによる） |
| 再試行 | `FilledButton` | **`onPressed`** で再度権限→取得 |
