# TASK-P1-26: 自炊（home）投稿のUIフロー（外食と分岐）

> **親ドキュメント**: [whoeats-screen-spec-v1.md](../../whoeats-screen-spec-v1.md) の **6.7 投稿作成画面**・**4.2 投稿作成プロンプト**（自炊トグル）／[whoeats-product-spec-v1.md](../../whoeats-product-spec-v1.md) の自炊まわり  
> **ブランチ名の例**: `feature/p1-26-home-post-flow`

---

## 目的

- ユーザーが **「自炊」を選んだとき**に、**店まわりの画面が出ずに迷わない**導線にする（画面仕様の「`restaurant` 時だけ店」に合わせる）。
- 投稿完了後に **自炊であることが分かり、前向きな一言**が出るなど、プロダクト仕様の「肯定的フィードバック」の最低限を満たす（文言はPM・非エンジニアで確定）。

---

## 説明

### アプリ上でどう見えるか

- 投稿作成で **外食／自炊** を切り替える（トグルまたはセグメント）。**自炊**を選ぶと、**店候補・地図・位置による近傍店**のブロックは **表示しない／スキップ**する。
- 外食のときは従来どおり **店の確認・手動変更**へ進む。
- 送信直後に、自炊なら **短い完了メッセージ**やイラスト枠（任意）を出してよい（仕様書のトーンに合わせる）。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **`post_type` / `home`** | データ上「自炊投稿」。店のID（`place_id`）は **null** で送る想定（DB設計は `doc/db-table-design-final-mvp.md`）。 |
| **`restaurant`** | 外食。店のIDが **必須** になる。 |

### 前提（先に終わっていること）

- PM最小の投稿フローがあり、**種別をAPIに渡せる**（`P1-01` / `P1-02`）。
- [whoeats-screen-spec-v1.md](../../whoeats-screen-spec-v1.md) **6.7** を読み、**「店舗候補を確認する（restaurant時）」** の条件分岐をそのまま実装方針にする。

---

## 方法

### 非エンジニアの方へ（進め方）

1. **自炊トグル／セグメントのラベル**を決める（例:「外で食べた」「おうち・自炊」）。**5.2 の「料理名（店名）」** は自炊時は **「料理名」だけ** に見えるよう、ラベル案を2パターン出す。
2. 自炊で投稿が終わったあとに出す **1文**（例:「自炊記録ついたね！」など。ペナルティ表現は禁止はプロダクト仕様参照）をPMが承認する。
3. 確認手順書を作る: **外食1本→自炊1本** の順で、**店画面が出ない／出る**が仕様どおりかチェックする。

### エンジニアの方へ（実装の進め方）

1. 画面に **`postType` 状態変数**（`'restaurant' | 'home'`）を置く。切替は **`SegmentedButton`** または **`Switch` + ラベル`**（`Switch` なら **`value`**, **`onChanged`**）。
2. **`if (postType == 'restaurant')`** のときだけ、**店候補ウィジェット・位置取得（`P1-23`）・手動検索**を **`Visibility`** や **`AnimatedSwitcher`** で出し分ける。
3. API送信時: `home` なら **`place_id` を送らない／null`**。サーバー契約に合わせる（`P1-01` のJSONと一致）。
4. マップ上の扱いは **別判断**（ピンを出さない等）。必要なら `P1-27` またはマップ担当と **重複しない**ようPRの範囲を書く。

### 使うとよいウィジェット・プロパティの例

| やりたいこと | ウィジェット例 | プロパティの例 |
|--------------|----------------|----------------|
| 出し分け | `Visibility` | **`visible: postType == 'restaurant'`** |
| 2択の種別 | `SegmentedButton<String>` | **`segments`**, **`selected`**, **`onSelectionChanged`** |
| 自炊の一言 | `SnackBar` 完了後 | **`content: Text('...')`** |

## 確認

- [ ] `home` のとき **店検索・候補リストが出ない**（または無効で理由が分かる）。
- [ ] `restaurant` のときだけ **店フローが必須**で、未入力では送れない。
- [ ] APIに **`post_type`（または契約上の同等フィールド）** が正しく付く。
- [ ] 自炊完了時の **一文**が仕様のトーンと一致する（PM承認済み）。
- [ ] PRに外食／自炊それぞれのスクショ。
