# TASK-P1-06: `@user_code` でユーザーを検索する

> **親ドキュメント**: [TASKS.md](../TASKS.md) の「TASK-P1-06」  
> **ブランチ名の例**: `feature/p1-06-user-search`

---

## 目的

- `@` から始まる **ユーザー固有のコード** で、ユーザーを検索できるようにする。
- 検索結果から **フォロー** など次の動きに進める。

---

## 説明

### アプリ上でどう見えるか

- 画面上部に **検索欄**。文字を打つと候補リストが出る。
- 1行タップで **プロフィール** へ行く、またはその場でフォローできる（仕様どおり）。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **前方一致** | 「入力の先頭から同じ文字列で始まるものだけ」ヒットする検索の仕方。 |
| **user_code** | ユーザーごとに1つだけ付く **短いID**（仕様書参照）。 |

### 前提（先に終わっていること）

- 検索APIの仕様（クエリ名・レスポンスのフィールド）が `doc` にある。
- `@` を付けるか付けないかの **表記ルール** をPMに確認する。

---

## 方法

### 非エンジニアの方へ（進め方）

1. **ヒント文**（プレースホルダ）を決める（例:「@からユーザーIDを入力」）。
2. **0件のとき**に出す一言（「該当するユーザーがいません」など）を決める。
3. 打ち間違いが多いので、**大文字小文字**を区別するかPMに確認。

### エンジニアの方へ（実装の進め方）

1. 入力は **`TextField`**。先頭に `@` を強制するなら **`inputFormatters`** で制御するか、表示だけ `@` を付ける。
2. 入力が変わってから **300ms〜500ms 待ってから検索**（**`debounce`**）するとサーバー負荷が減る。簡易なら **`onChanged`** で毎回呼ぶが上限注意。
3. 結果は **`ListView.builder`**。1行は **`ListTile`** の **`leading: CircleAvatar`**（アイコン）、**`title: Text(displayName)`**、**`subtitle: Text('@$userCode')`** が分かりやすい。
4. フォロー導線は **`P1-05`** と同じボタン部品に寄せると見た目が揃う。

### 使うとよいウィジェット・プロパティの例

| やりたいこと | ウィジェット例 | プロパティの例 |
|--------------|----------------|----------------|
| 検索欄 | `TextField` | **`decoration: InputDecoration(prefixText: '@')`** など |
| クリアボタン | `TextField` | **`decoration` の `suffixIcon: IconButton`** で `controller.clear()` |
