# TASK-P1-02: 投稿画面（PMは「最小」まで、あとは22〜27＋必要なら29）

> **親ドキュメント**: [TASKS.md](../TASKS.md) の「TASK-P1-02」  
> **方針**: PM は **「投稿できるところまで」** の画面・導線を先に用意する。キャプション・位置・公開範囲の磨き込みは [P1-22](./TASK-P1-22-post-caption-validation.md)〜[P1-25](./TASK-P1-25-post-visibility-ui.md)。**自炊**は [P1-26](./TASK-P1-26-home-cooking-post-flow.md)、**種別バッジ**は [P1-27](./TASK-P1-27-post-type-badges.md)、**誰といるか**は [P1-29](./TASK-P1-29-post-companion-field.md)。ホームの通知・マップシート等は [README](./README.md) の P1-28〜34。

---

## 目的

- ユーザーが **写真を選び（または撮り）、店を確認して、投稿ボタンで送れる** 最短ルートを用意する。
- 細かい文言・入力制限・位置の取り方は **別タスク** に分け、最初の1週間で詰まらないようにする。

---

## 説明

### アプリ上でどう見えるか

- いわゆる「投稿フロー」の画面。大きくは **(1) 写真 (2) 店の確認 (3) 投稿する** の順です。
- 「最小」では、見た目は簡素でもよいので、**最後まで通る**ことが最優先です。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **最小（MVP）** | プロが後から磨く前提で、「一度でも成功体験ができる」ライン。 |
| **公開範囲** | その投稿を誰が見られるか（全体／友達だけ／自分だけ など）。仕様書の3段階に合わせる。 |

### 前提（先に終わっていること）

- [TASK-P1-01](./TASK-P1-01-post-api.md) が通っていて、投稿APIに実際に送れること。

---

## 方法

### 非エンジニアの方へ（進め方）

1. **画面の文案**は、まず仕様書の「撮る → 店確認 → 投稿」の順を崩さないことだけ確認してください。
2. 細かい **プレースホルダ**（入力例の薄い文字）や **文字数の上限表示**は `P1-22` に任せてよいです。
3. 実機で「**最後まで投稿できた**」かどうかを **チェックリスト**で確認してください（下の「確認」参照）。

### エンジニアの方へ（実装の進め方）

1. 投稿フロー用の **新しい画面ファイル** を `lib/src/features/...` の適切なフォルダに追加する（フォルダ名はチームで決めてよいが、**投稿は1か所にまとめる**とあとで探しやすい）。
2. 写真: `ImagePicker` 等で取得 → プレビュー用に `Image.file(...)` の **`fit`** プロパティで **`BoxFit.cover`** などを指定すると、枠に収まりやすい。
3. 店の候補: まずは **1件だけ表示** でもよい。変更は別画面またはボトムシートで **検索欄は `TextField`** の **`decoration: InputDecoration(hintText: '...')`** でヒントを出せる。
4. 投稿ボタン: `ElevatedButton` の **`onPressed`** で API を呼ぶ。**送信中は `onPressed` を null にする**（ボタンの **`onPressed: isLoading ? null : () { ... }`**）と二重送信を防げる。
5. 公開範囲: 最小では **`SegmentedButton`** または **`RadioListTile`** の **`groupValue` / `onChanged`** で3択が選べればよい（見た目の磨き込みは `P1-25`）。

### 使うとよいウィジェット・プロパティの例

| やりたいこと | ウィジェット例 | プロパティの例（意味） |
|--------------|----------------|------------------------|
| 写真を表示 | `Image` | **`fit`**: 枠の中の収め方 |
| 文字を入力 | `TextField` | **`maxLines`**: 行数 / **`maxLength`**: 文字数上限（キャプション詳細はP1-22） |
| 送信中に無効化 | `ElevatedButton` | **`onPressed`**: 送信中は `null` にする |
| 3択 | `SegmentedButton` | **`segments`**, **`selected`**, **`onSelectionChanged`** |

## 確認

- [ ] 実機またはエミュレータで、**投稿完了まで一連で通る**。
- [ ] 通信が失敗したときに **アプリが落ちない**（エラー表示だけでよい最小）。
- [ ] 投稿後、タイムラインまたは一覧のどこかで **自分の投稿が見える**。
- [ ] 「キャプションの気持ちよさ」は未完でもよい、とチームで共有できている。

## タスク

1. 投稿用の画面（ルート）を1本追加する。
2. 写真選択 → プレビューまでつなぐ。
3. 店IDの確定（仮でよいので）までつなぐ。
4. 公開範囲をAPIの形に合わせて送る。
5. 投稿APIを呼び、成功時に前の画面へ戻る or 完了表示を出す。
6. メンバー向けに「最小でここまでできた」と知らせ、`P1-22`〜`27`・`29` などの配布判断をする。
