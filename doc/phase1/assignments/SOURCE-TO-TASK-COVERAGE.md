# 仕様 → 個票 カバレッジ表（見落とし防止）

> **なぜこれがあるか**: 画面仕様・プロダクト仕様には「一文で書いてあるだけ」の要件が多く、**個票に落ちていないと実装もテストも飛ばされる**。ソースごとに **個票IDを1行で固定**し、表と個票を **同時に**更新する。

---

## 使い方（配布・締めの前に）

1. **表A** を上から読み、**GAP** が無いか確認する（後回しなら **意図的保留 + 理由** を同表に書く）。
2. 仕様を増やしたら **先にこの表を更新し、次に個票ファイルを追加**する。
3. 個票だけ増やして表を更新しないこと。

---

## ステータスの意味

| 記号 | 意味 |
|------|------|
| **OK** | 個票（またはPM前提）に落ちている。 |
| **部分** | 複数個票に分割。表の「個票」列にすべて書く。 |
| **GAP** | 個票が無い（**禁止。見つけたら個票を増やして OK にする**）。 |
| **P2** | Phase2。`doc/phase2/TASKS.md` を参照。 |
