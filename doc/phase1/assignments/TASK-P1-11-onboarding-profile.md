# TASK-P1-11: はじめてログインしたあとのプロフィール初期設定

> **親ドキュメント**: [TASKS.md](../TASKS.md) の「TASK-P1-11」  
> **ブランチ名の例**: `feature/p1-11-onboarding-profile`

---

## 目的

- 初めてアプリに入った人が、**名前・ユーザーID（@から始まるコード）・アイコン（任意なら任意）** を登録してから本編に進める。
- 2回目以降のログインでは **この画面を出さない**。

---

## 説明

### アプリ上でどう見えるか

- ログイン直後に **「プロフィールを設定しましょう」** のような画面。
- 入力して「次へ」「はじめる」でホームなどへ。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **初回判定** | 「まだ初期設定が終わっていないユーザーか」をサーバーまたは端末で判定すること。 |
| **user_code** | 他のユーザーから検索されるID。**重複しない**必要がある。 |

### 前提（先に終わっていること）

- ログイン・ログアウトが動く（PM）。
- `users` テーブルに自分の行が作られる、または作るAPIがある。

---

## 方法

### 非エンジニアの方へ（進め方）

1. 各入力の **必須／任意** と **最大文字数** を表にする（仕様書＋PM確認）。
2. **user_code が重複したとき**のエラーメッセージを人間向けに書く（例:「このIDはすでに使われています」）。
3. 初回だけ出ることを **実機で2アカウント** 使って確認する手順をメモする。

### エンジニアの方へ（実装の進め方）

1. ルートの **`MaterialApp`** の **`home`** または **`routes`** の手前で、**「未設定なら `/onboarding`」** に **`Navigator.pushReplacement`** するパターンが分かりやすい（実装は既存構造に合わせる）。
2. 入力は **`TextFormField`** の **`validator`**。**`user_code`** は英数字など、**`FilteringTextInputFormatter`** で制限してもよい。
3. 送信は **`FilledButton`**。成功後 **`users` のフラグ更新** または **プロフィール完成API** を呼ぶ（PM仕様に従う）。
4. 成功後 **`Navigator.pushAndRemoveUntil`** で **戻るボタンで初期設定に戻れない**ようにするのが安全なことが多い。

### 使うとよいウィジェット・プロパティの例

| やりたいこと | ウィジェット例 | プロパティの例 |
|--------------|----------------|----------------|
| 説明文 | `Text` | **`style: Theme.of(context).textTheme.bodyMedium`** でトーン統一 |
| 必須マーク | `InputDecoration` | **`labelText: '表示名 *'`** など |
