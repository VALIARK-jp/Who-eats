# TASK-P1-05: フォロー／フォロー解除を画面につなぐ

> **親ドキュメント**: [TASKS.md](../TASKS.md) の「TASK-P1-05」  
> **ブランチ名の例**: `feature/p1-05-follow`

---

## 目的

- 友達候補の一覧などで **「フォローする」「外す」** が本番データで動くようにする。
- ボタン表示と **実際のフォロー状態** が食い違わないようにする。

---

## 説明

### アプリ上でどう見えるか

- ユーザー名の横に **フォロー中／フォローする** のようなボタンまたはテキスト。
- タップすると状態が切り替わり、**一覧を開き直しても同じ表示**になる。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **フォロー** | 相手の更新を見たいという関係。アプリでは「片方向の関心」。 |
| **相互フォロー** | お互いフォローしている状態。仕様上「友達」と呼ぶことが多い（詳細は仕様書）。 |

### 前提（先に終わっていること）

- フォローAPIの **URL・送るJSON・返ってくるJSON** が `doc` に書いてある（PM）。
- ログイン済みで、**「誰が操作しているか」** がサーバーに伝わる。

---

## 方法

### 非エンジニアの方へ（進め方）

1. ボタンの **日本語ラベル** を統一する（例:「フォローする」「フォロー中」「フォロー解除」）。デザインがあればそれに合わせる。
2. 処理中は **連打できない** 方がよい、とチームで決め、エンジニアに伝える。
3. 受け入れ時に **Aさん→Bさんをフォロー→一覧を閉じて再度開く** まで試す。

### エンジニアの方へ（実装の進め方）

1. 候補1行は **`ListTile`** が定番。右側に **`Trailing`** として **`FilledButton`** または **`OutlinedButton`** を置く。
2. 状態が2種類以上なら **`ElevatedButton.styleFrom`** で色を変える、または **`Text`** だけ切り替え。
3. API成功後に **`setState`** または状態管理（Riverpod 等）で **ローカル状態を更新**。失敗時は **`SnackBar`**。
4. 同じユーザーを **短時間に二重リクエスト** しないよう、**`onPressed` を送信中 null`** または **`debounce`**（必要なら）。

### 使うとよいウィジェット・プロパティの例

| やりたいこと | ウィジェット例 | プロパティの例 |
|--------------|----------------|----------------|
| 行の右にボタン | `ListTile` | **`trailing:`** に `SizedBox(width: 96, child: FilledButton(...))` |
| 無効化 | `FilledButton` | **`onPressed`**: `null` でグレーアウト |

## 確認

- [ ] フォロー後、**再表示してもフォロー中**と出る。
- [ ] 解除後も同様に **一貫**している。
- [ ] 失敗時にユーザーへ **一言フィードバック**がある。
- [ ] DBスキーマ変更を含まない。
- [ ] PR にスクショがある。
