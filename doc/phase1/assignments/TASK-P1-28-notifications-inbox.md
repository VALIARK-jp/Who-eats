# TASK-P1-28: 通知（ホーム右上→一覧・未読）

> **根拠仕様**: [whoeats-screen-spec-v1.md](../../whoeats-screen-spec-v1.md) **5.1**（通知導線）、**6.2**（ホームからの行動）  
> **ブランチ名の例**: `feature/p1-28-notifications`

---

## 目的

- ホーム上部の **通知アイコン**から、**コメント／リアクション／フォロー**などのお知らせを一覧で見られるようにする（仕様で列挙された種別をカバーする）。
- **未読件数**または **未読の見た目**が分かる（仕様の最小。プッシュ通知は別スコープ可）。

---

## 説明

### アプリ上でどう見えるか

- ベルまたは同種のアイコンをタップ → **通知一覧画面**（またはボトムシート）。
- 1行タップで **該当投稿・プロフィール**などへ飛ぶ（APIが返す `target` に従う）。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **通知一覧** | サーバーが返すイベントのリストを時系列で並べた画面。 |
| **未読** | まだ開いていない行。点・太字・背景色などで示す。 |

### 前提（先に終わっていること）

- 通知取得APIの **JSON形**（種別・本文・遷移先ID）が `doc` にある、または PM がモックを置いた。
- DB に **通知テーブルが無い**場合は、MVP で **他手段**（例: クライアントのみ）にするか **PM がAPI方針を先に固定**する。

---

## 方法

### 非エンジニアの方へ（進め方）

1. 種別ごとに **1行の日本語テンプレ**を決める（例:「○○さんがあなたの投稿にいいねしました」）。
2. **0件**のときの文言と、**エラー時**の文言を決める。
3. 行をタップしたあと **どの画面に着地するか** を表にする（種別×遷移先）。

### エンジニアの方へ（実装の進め方）

1. ホーム `AppBar` の **`actions`** に **`IconButton(icon: Icon(Icons.notifications_outlined), onPressed: ...)`**。未読バッジは **`Badge`** で **`child: IconButton(...)`** を包むか **`Stack` + `Positioned`** で小さな **`Container`**。
2. 一覧は **`ListView.separated`** + **`ListTile`**。**`leading: CircleAvatar`**（アクター）、**`title`/`subtitle`** に要約。
3. 既読化は **タップ時に API PATCH** または **ローカル保存**（PM契約に従う）。

### 使うとよいウィジェット・プロパティの例

| やりたいこと | ウィジェット例 | プロパティの例 |
|--------------|----------------|----------------|
| 未読ドット | `Badge` | **`isLabelVisible`**, **`label: Text('9+')`**（件数ポリシーはPM） |
| 下から一覧 | `showModalBottomSheet` | **`isScrollControlled: true`** |
