# TASK-P1-09: 読み込み中・空・エラーの見た目をそろえる（横断）

> **親ドキュメント**: [TASKS.md](../TASKS.md) の「TASK-P1-09」  
> **ブランチ名の例**: `feature/p1-09-state-ui`  
> **注意**: **第2波推奨**。他の人のPRとぶつかりやすいので、PMと「いつから」「どの画面まで」を決めてから始める。

---

## 目的

- 「読み込み中」「データがない」「失敗した」「権限がない」などのときに、**アプリ全体で同じような見た目・文言のトーン**になるようにする。
- ユーザーが **次に何をすればよいか** を迷いにくくする。

---

## 説明

### アプリ上でどう見えるか

- 各画面で、同じ種類の状態なら **同じパターンのイラスト・文言・ボタン**（例:「再読み込み」）が出るイメージ。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **横断** | たくさんの画面にまたがって、同じルールを当てはめること。 |
| **オフライン** | インターネットに繋がっていない状態。 |

### 前提（先に終わっていること）

- 主要画面の機能が一通り動いている（でないと「空」と「未実装」が区別つかない）。
- PMまたはデザインと **文言リスト** のたたき台があるとスムーズ。

---

## 方法

### 非エンジニアの方へ（進め方）

1. 次の4〜5種類それぞれについて **日本語の定型文** を1つずつ決める: **読み込み中 / まだない / 失敗 / 権限が必要 / オフライン気味**。
2. 「再試行」ボタンを付けるかどうか、**画面ごと**に必須か任意かを表にする。
3. スクリーンショットを撮り、**Before（バラバラ）→After（そろった）** をPR用に残す。

### エンジニアの方へ（実装の進め方）

1. 小さな部品にまとめる例: **`StatelessWidget` 名前付き `AppEmptyState`** のように **`title`**, **`message`**, **`actionLabel`**, **`onAction`** を **プロパティ（コンストラクタの引数）** で渡す。
2. 読み込みは **`CircularProgressIndicator`** を **`Center`** で包むパターンを共通化。 **`semanticsLabel`** を付けるとアクセシビリティ向上。
3. エラーは **`SelectableText`** や **`Text`** + **`FilledButton.tonal(...)`** の **`onPressed`** で再試行。
4. 既存画面では **`FutureBuilder`** / **`AsyncValue`** などの分岐を、共通ウィジェット呼び出しに置き換えていく（**1画面ずつPR** に分けるとレビューしやすい）。

### 使うとよいウィジェット・プロパティの例

| やりたいこと | ウィジェット例 | プロパティの例 |
|--------------|----------------|----------------|
| 縦中央寄せ | `Center` | **`child`** に状態UI |
| 余白 | `Padding` | **`padding: EdgeInsets.all(24)`** など統一値 |
| 再試行 | `FilledButton` | **`onPressed`**, **`child: Text('再読み込み')`** |

## 確認

- [ ] PMと合意した **画面リスト** がすべて確認済み。
- [ ] 各状態で **同系統のレイアウト**になっている（例外はPRに理由記載）。
- [ ] 画面を触って **落ちない**。
- [ ] PRに Before / After のスクショがある。

---

## タスク

1. PMと対象画面・優先順位を合意する。
2. 共通ウィジェット（またはヘルパ関数）を1つ作る。
3. 画面を1つずつ置き換える（PRは分割可）。
4. 文言を非エンジニアレビューに載せる。
5. `flutter analyze` と PR。
