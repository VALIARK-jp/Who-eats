# TASK-P1-10: 投稿が失敗したときに、もう一度試せるようにする

> **親ドキュメント**: [TASKS.md](../TASKS.md) の「TASK-P1-10」  
> **ブランチ名の例**: `feature/p1-10-post-retry`

---

## 目的

- 通信エラーなどで投稿に失敗しても、ユーザーが **諦めずにもう一度送れる**。
- 可能な範囲で **入力した内容（写真・文・店・公開範囲）が消えない**ようにする。

---

## 説明

### アプリ上でどう見えるか

- 失敗した直後に **「もう一度送る」ボタン** または **自動で再試行する回数の表示**。
- 写真が消えてしまうとユーザーが激しく困るので、**消えない方がよい**のが基本。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **リトライ** | もう一度同じ処理を試すこと。 |
| **保持** | 画面を閉じない限り、入力内容をメモリに残すこと。 |

### 前提（先に終わっていること）

- 投稿フロー（PM最小または `P1-02`）が存在する。
- 失敗を意図的に再現する方法（機内モード等）を **確認担当** が知っている。

---

## 方法

### 非エンジニアの方へ（進め方）

1. **自動で何回まで**再送するか、**手動ボタンのみ**かをPMに決めてもらう。
2. 失敗時の **日本語**（例:「接続できませんでした。通信状況を確認のうえ、もう一度お試しください」）を用意する。
3. 確認時に **機内モードON→投稿→OFF→リトライ** の手順をメモに残す。

### エンジニアの方へ（実装の進め方）

1. 投稿用の状態を **`StatefulWidget`** の **`State`** に持つか、**Riverpod の `Notifier`** にまとめる。**写真は `XFile` / `Uint8List` / パス**のいずれか一貫した持ち方にする。
2. 失敗時: **`SnackBar`** に **`action: SnackBarAction(label: '再試行', onPressed: ...)`** を付けるのが手軽。画面内に **`FilledButton`** を置いてもよい。
3. 送信中は **`ElevatedButton(onPressed: null)`** や **`AbsorbPointer`** で二重送信を防ぐ。
4. **`P1-24`**（撮影→店の作り込み）と被る場合は、**どちらのPRで何をやるか** PMに線引きしてもらう。

### 使うとよいウィジェット・プロパティの例

| やりたいこと | ウィジェット例 | プロパティの例 |
|--------------|----------------|----------------|
| 再試行の足 | `SnackBar` | **`action: SnackBarAction(...)`** |
| 送信中オーバーレイ | `Stack` | 上に **`ModalBarrier`** や半透明 **`Container`** |

---

## 確認

- [ ] 意図的に失敗させても **アプリが落ちない**。
- [ ] 再試行で **同じ内容を再送できる**（仕様の範囲内）。
- [ ] 成功後に **二重投稿にならない**（サーバー側の冪等性はPM確認）。
- [ ] PRに手順とスクショ。

---

## タスク

1. 投稿フローの状態の持ち方を決める。
2. 失敗検知とユーザー向けメッセージを入れる。
3. 再試行導線を実装する。
4. 保持できる範囲をコードコメントまたはPRに明記する。
5. PR提出。
