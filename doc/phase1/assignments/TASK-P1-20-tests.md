# TASK-P1-20: 自動テストと手動チェック項目を足す

> **親ドキュメント**: [TASKS.md](../TASKS.md) の「TASK-P1-20」  
> **ブランチ名の例**: `feature/p1-20-tests`

---

## 目的

- あとから機能を足しても **壊れにくい**ように、重要なところに **自動テスト** を付ける。
- リリース前に誰でもできる **手動チェックリスト** を残す。

---

## 説明

### アプリ上でどう見えるか

- ユーザー向け画面は変わらないことが多い（裏側の品質タスク）。

### 用語ミニ辞典（このタスクだけ）

| 用語 | 意味 |
|------|------|
| **unitテスト** | 小さな関数やクラスだけを切り離して動かすテスト。 |
| **widgetテスト** | 画面の部品をプログラムでタップして動きを確認するテスト。 |

### 前提（先に終わっていること）

- テスト対象の機能が **一通り動いている**。
- PMと **どのフローを優先するか** 合意している。

---

## 方法

### 非エンジニアの方へ（進め方）

1. **手動チェックリスト**を作る: 例「ログイン→投稿→タイムラインで見える→削除」。
2. リリース前に **チェックボックス** で自分の端末でも試す。
3. 失敗したら **スクショ付きでIssue**（再現手順付き）。

### エンジニアの方へ（実装の進め方）

1. **`test/`** フォルダに追加。既存の **`widget_test.dart`** を参考にする。
2. **`flutter_test`** の **`testWidgets`** 内で **`await tester.pumpWidget(MyApp());`** → **`await tester.tap(find.text('...'));`** → **`await tester.pumpAndSettle();`**。
3. 純粋な変換ロジックは **`test('description', () { expect(...); });`** で unit 化。

### 使うとよいAPIの例（widgetテスト）

| やりたいこと | 関数例 | 説明 |
|--------------|--------|------|
| 文字を探す | `find.text('ログイン')` | 画面上の `Text` を検索 |
| ボタンを押す | `tester.tap(find.byType(FilledButton))` | 最初のボタン等（ **`find.byKey(Key('login'))`** の方が安全なことが多い） |
