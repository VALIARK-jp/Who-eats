# Who eats タスク一覧（PMが5フロー固定した後）

> 前提: PMが以下5フローを仕様確定済み  
> 1) 投稿作成（restaurant/home分岐）  
> 2) タイムライン取得（public/friends/private + block）  
> 3) フォロー/解除（相互フォロー判定）  
> 4) 店詳細取得（places + posts + 集計）  
> 5) マップピン取得（キャッシュ/集計/外部API分担）
>
> **配布前の実装分担（運用）**: 1・2・4・5 はPMが縦切りで先に疎通。3（フォロー）はメンバー実装レーンに残す。投稿1は「投稿できる最小」までをPMとし、キャプション・位置デフォルト等のUXは `doc/phase1/TASKS.md` の「投稿（PM最小のあと）」を参照。

---

## 1. 仕様・契約の反映

1.1 固定した5フローの仕様を `doc/` に反映（Mermaid + テキスト説明）  
1.2 API I/F一覧（endpoint / method / req / res / error）を作成  
1.3 フロント実装用のモックJSONを各機能分作成  
1.4 「今回やらないこと（Non-goal）」を機能ごとに明記  

## 2. バックエンド実装（DB変更なし）

2.1 投稿作成APIを5フロー定義通りに実装  
2.2 タイムライン取得APIを visibility + block 条件で実装  
2.3 フォロー/解除APIと相互判定ロジックを実装  
2.4 店詳細API（places + posts + 集計）を実装  
2.5 マップピン取得API（キャッシュ/集計/外部API分担）を実装  
2.6 共通エラー形式（403/404/409/422/500）を統一  

## 3. フロント実装（Flutter）

3.1 モックデータ依存箇所をAPI接続に置換（段階的）  
3.2 投稿作成フローUIを本番データに接続  
3.3 タイムライン表示を本番データ + visibility反映に更新  
3.4 フォロー/解除UIを本番データに接続  
3.5 店詳細表示を本番データ + 集計表示に接続  
3.6 マップピン描画を本番データ接続へ更新  
3.7 ローディング/空状態/エラーUIを統一  
3.8 再試行導線（ネットワーク失敗時）を追加  

## 4. UI品質・デザイン整合

4.1 `doc/UIv2.png` との差分洗い出し（画面ごと）  
4.2 色・余白・タイポを `AppTheme` 基準で統一  
4.3 ボトムシート/カードのコンポーネントルールを統一  
4.4 アクセシビリティ（コントラスト/タップ領域/ラベル）改善  
4.5 UI最終差分チェック（Before/Afterスクショで確認）  

## 5. マップ・3Dピン仕上げ

5.1 マップズーム段階ごとの表示挙動を最終調整  
5.2 3Dピン表示の端末差（iOS/Android）検証  
5.3 投稿ピン/通常ピンの視認性改善  
5.4 パン/ズーム中のFPS挙動確認（移動中低FPS、停止後30fps）  
5.5 店詳細ボトムシート遷移の操作感調整  

## 6. テスト（手動 + 自動）

6.1 機能別テストケース作成（正常系/異常系）

6.3 ユニットテスト（UseCase/Repository）追加  
6.4 ウィジェットテスト（主要画面）追加
